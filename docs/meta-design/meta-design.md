## Key facts
- **PARKED — not implemented.** This entire layer is a design vision, explicitly NOT being built now. It exists only as three brief documents (meta-design brief, use-case catalog, karma-ledger notes). Treat everything below as intent, not current behavior.
- **The Karma Ledger does not exist in code.** `karma` appears nowhere in `src/`. There is no data structure, no tracker, no persistence, no consuming system.
- **The only code that exists** is the zoom-as-peering-at-fate effect: `src/app/components/HeavenlyVeil.tsx`, `src/app/components/ObfuscatedLifespan.tsx`, and `src/app/hooks/useZoomDetector.ts`. The lifespan number is displayed obfuscated and becomes progressively MORE distorted as the player zooms in (reality defends its secrets) — the reference template the brief calls "the Lifespan Blur Pattern."
- **There is one dead event.** `player:peered_at_fate` (with a `zoomLevel: number` payload) is defined in `src/app/types/events.ts:10` and emitted from `ObfuscatedLifespan.tsx:25`, but **has no listener** anywhere (`src/app/services/`, `src/main.tsx`). It is wired to fire and then nothing consumes it. This is the single thread connecting current code to the parked meta-layer.
- **Four pillars, strict dependency order: 1 -> 2 -> 3 -> 4.** Each reads from those before it. (1) Karma Ledger is the foundational data layer; (2) Progressive UI Revelation; (3) Prestige/Tribulation loop; (4) Narrative Diegesis is the output layer.
- **Core principle:** detect a player-level action, interpret it as a character-level action inside xianxia cosmology, respond diegetically. No tooltips, no achievement pop-ups — "the heavens simply act."
- **The behavior->response catalog (below) is the richest content** — 7 categories, ~30 use cases, each with detection method, diegetic name, and game response. Preserved verbatim as a table.

## Status and what actually exists today
This layer is parked. None of the four pillars are implemented as systems. The codebase contains a single proof-of-concept of the underlying pattern (zoom detection -> distorted lifespan), plus a dangling event that was meant to feed a karma tracker that does not exist. If/when this work resumes, the brief prescribes tackling one pillar per session in dependency order, starting with the Karma Ledger data model and 2-3 detectable behaviors (zoom, tab-switch, click patterns), building tracking silently before building any system that reads from it.

## Pillar 1: The Karma Ledger (foundational data layer)
A hidden, multi-dimensional record that silently observes player-level behaviors and interprets them through xianxia cosmology. The player never sees a "karma score"; other systems query the ledger when deciding how to respond. Open design questions from the brief: single-axis vs. multi-dimensional (candidate axes: Curiosity, Patience, Mercy, Hubris, Defiance); whether karma is ever visible (late-game enlightenment reward, or never); false-positive handling via thresholds (one zoom = a glance, ten = deliberate prying); whether awareness of the system changes it ("Heisenberg's karma"); how karma interacts with prestige.

**Persistence rules:** within a run, all behaviors accumulate. Across prestiges, the ledger persists in full ("the character may forget, but the Heavenly Dao does not" — lets NPCs reference past-life behavior without breaking fiction). Across hard resets, undecided — reserved for highest-impact moments if ever implemented (Undertale-style save memory).

## Pillar 2: Progressive UI Revelation (the interface as cultivation)
Every UI element is framed as the character perceiving more of reality; the player's growing understanding of systems mirrors the character's growing understanding of the cosmos. Each reveal is a narrative beat, never a silent UI update. Hidden elements leave traces (a flickering dot from game start that later resolves into qi — foreshadowing through UI, not dialog). The Karma Ledger can accelerate revelation ("high spiritual root").

Revelation arc (stage -> what's seen -> what's hidden -> trigger):
- **Mortal:** unlabeled shapes (red square = strength, blue circle = agility), no numbers, no stat panel. Trigger: game start.
- **Awakened Mortal:** shapes get labels, still no numbers. Trigger: first event requiring stat awareness.
- **Martial Artist:** full stat panel with numbers, XP bars — looks like a "normal" idle game. A faint flickering element (qi foreshadowing). Trigger: character "perceives their own body."
- **Early Cultivator:** qi bar appears, cultivation techniques visible, flickering element resolves. Trigger: hitting the ceiling of martial arts.
- **Cultivator:** prestige mechanics / reset / tribulation option visible, cross-run persistence apparent. Trigger: first breakthrough attempt.
- **Immortal+:** automation unlocks ("Dao Comprehension"); the meta-game becomes the game.

## Pillar 3: The Prestige/Tribulation Loop (resets as narrative)
Prestige IS the xianxia narrative — breaking through means destroying your foundation to rebuild stronger. Loop: accumulation phase -> diegetically-signaled tribulation trigger (sky darkens, NPCs comment, UI shifts; player chooses when) -> the tribulation itself (an active gameplay sequence, NOT a confirmation dialog, shaped by karma/path/choices) -> outcome (success = reset with multipliers + new realm + UI reveals; failure = "cultivation deviation," partial reset, karmic consequences — still interesting, not just punishing) -> new cycle with persistent knowledge/karma.

Tribulation types: Heavenly Lightning (standard resource-gated check), Inner Demon (karma-driven, UI may become unreliable), Heart Demon Trial (curiosity-driven, from zoom/source-inspection karma), Fate Tribulation (pattern-driven, targets cross-run tendencies). Failure-as-content options: partial reset, deviation path, demonic cultivation unlock.

Persistence across prestiges: **Always persists** — Karma Ledger, prestige currency ("Heavenly Merit" or equiv.), highest realm reached, meta-progression unlocks (automation tiers). **Conditionally** — partial UI revelation, NPC recognition, technique knowledge (re-leveled). **Always resets** — mortal-realm stats, mortal resources/items, cultivation level within a realm, event/quest progress.

## Pillar 4: Narrative Diegesis (the world responds)
Output layer: nothing should feel "gamey" in a way that breaks fiction. Player-as-entity acknowledgment escalates by level: **Ambient** (world reflects meta-behavior, no comment — e.g. a shrine to "a cycle-walker"), **Indirect** (NPCs sense a presence/looping fate they can't identify), **Direct** (a high-level entity addresses the watching presence as a cosmic force), **Transcendent** (system and narrative collapse — the raw idle mechanics ARE the highest plane; "it was always a game, and the game was always real"). NPC framework reacts to patterns not single events, scaled by awareness tier (mortals feel it; martial masters sense aura/fate; immortals perceive the prestige cycle). Unreliable presentation: breakthrough distortion (UI lies during tribulations), memory bleed (past-run fragments), perception-gated content (invisible at lower cultivation). Environmental storytelling accumulates across runs (shrines, inherited NPC traits, landscape shifts).

## Cross-pillar interactions (intent)
Karma feeds all three other pillars: it can accelerate UI revelation (high curiosity = "high spiritual root"), determine tribulation type/difficulty, and drive NPC reactions, environmental change, and acknowledgment level. UI revelation and the tribulation loop interlock (each prestige tier unlocks new UI; failed prestiges distort it). Prestiges are the major plot beats; what persists across resets defines what the narrative can reference.
